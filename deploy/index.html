一、实验设置与统计口径

先把指标和范围讲清楚，结论才可信。

  • 数据与题目：自建中文电商库（8 表、800 订单、2024-06 ~ 2025-08），50 题分 easy / medium / hard，覆盖单表、2 表 JOIN、3 表 JOIN + HAVING + 子查询。
  • 指标：Valid SQL（能否执行）、严格 EX（结果行列完全一致）、答案等价 EX（本报告主指标）。
  • 答案等价 EX 定义：行数一致，且 gold 的每一列都能在模型结果里找到；允许模型多返回辅助列（如顺带带上销量/销售额），允许 ID 与名称等价（1 与「数码电子」视为同一个值），忽略列顺序。
  • 口径复核：逐题对照业务语义，累计修订 31 条题目本身的逻辑错误，其中 19 条留档复核（附修改前后 SQL 对照，明细见 reports/gold_sql_review.xlsx），其余为同题多轮迭代修订。典型问题：过滤条件写在 JOIN ON 里失效、ORDER BY 用明细列、缺聚合/GROUP BY、分母口径错、明细重复累加。
  • 缺失处理：接口异常产生的空输出按「缺失」处理，不计入分母（表中「有效题数」已扣除），避免把调用失败算成模型能力问题。本次加强提示下三模型均为 50/50 有效；消融组的 simple 档 deepseek-flash 为 49/50。
  • 消融实验：仅取 glm-4.5-flash 与 deepseek-flash，各跑「简单提示 / 加强提示」两档，共 4 组 × 50 题；qwen-plus 只参与横向对比。
为什么消融没有 qwen-plus？ 消融需要成对运行（模型 × 2 档提示），加千问意味着多 2 组全量调用；其响应延迟高、成本不合算，且它在横向对比中 hard 段（67%）明显低于 deepseek（87%），不改变消融结论方向。因此消融结论仅代表 glm 与 deepseek 两个模型，不外推到 qwen-plus。

四、典型案例

每个模型各取 1 条正确、1 条失败，对比 gold_sql 与模型生成 SQL。

正确 智谱 glm-4.5-flash Q36 · hard
各年龄段用户销售额怎么样
gold_sql
select case
  when u.age between 18 and 25 then '18-25岁'
  when u.age between 26 and 35 then '26-35岁'
  when u.age between 36 and 45 then '36-45岁'
  when u.age between 46 and 60 then '46-60岁'
  else '60岁以上'
end as age_bucket, sum(o.total_amount) as total_sales
from orders o left join users u on o.user_id = u.user_id
where o.status = '已完成'
group by age_bucket
order by age_bucket
模型生成 SQL
SELECT 
    CASE 
        WHEN u.age BETWEEN 18 AND 25 THEN '18-25岁'
        WHEN u.age BETWEEN 26 AND 35 THEN '26-35岁'
        WHEN u.age BETWEEN 36 AND 45 THEN '36-45岁'
        WHEN u.age BETWEEN 46 AND 60 THEN '46-60岁'
        WHEN u.age >= 61 THEN '60岁以上'
        ELSE '未知年龄段'
    END AS age_group,
    SUM(o.total_amount) AS total_sales
FROM users u
JOIN orders o ON u.user_id = o.user_id
WHERE o.status = '已完成'
GROUP BY age_group
ORDER BY age_group

gold_sql
select o.pay_type, count(distinct re.refund_id) * 1.0 / count(distinct o.order_id) from orders o join users u on o.user_id = u.user_id join regions r on u.region_id = r.region_id left join refunds re on o.order_id = re.order_id and re.refund_time >= '2024-12-31' and re.refund_time < '2025-01-01' where r.region_name = '华东' group by o.pay_type
模型生成 SQL
SELECT 
    pay_type,
    SUM(r.refund_amount) * 1.0 / 
        (SELECT SUM(total_amount) 
         FROM orders 
         WHERE status IN ('已完成', '已退款') 
         AND region_id = 1 
         AND strftime('%Y-%m', order_time) = '2024-12') AS refund_rate
FROM refunds r
JOIN orders o ON r.order_id = o.order_id
JOIN users u ON o.user_id = u.user_id
WHERE u.region_id = 1
AND strftime('%Y-%m', r.refund_time) = '2024-12'

华东区域不同支付方式的24年12月31日退款率分布情况
gold_sql
select o.pay_type, count(distinct re.refund_id) * 1.0 / count(distinct o.order_id) from orders o join users u on o.user_id = u.user_id join regions r on u.region_id = r.region_id left join refunds re on o.order_id = re.order_id and re.refund_time >= '2024-12-31' and re.refund_time < '2025-01-01' where r.region_name = '华东' group by o.pay_type
模型生成 SQL
SELECT d.pay_type,
       COALESCE(rf.refund_amount, 0) * 1.0 / NULLIF(d.total_amount, 0) AS refund_rate
FROM (
    SELECT o.pay_type, SUM(o.total_amount) AS total_amount
    FROM orders o
    JOIN users u ON o.user_id = u.user_id
    JOIN regions rg ON u.region_id = rg.region_id
    WHERE rg.region_name = '华东'
      AND substr(o.order_time, 1, 10) = '2024-12-31'
      AND o.status IN ('已完成', '已退款')
    GROUP BY o.pay_type
) d
LEFT JOIN (
    SELECT o.pay_type, SUM(r.refund_amount) AS refund_amount
    FROM orders o
    JOIN users u ON o.user_id = u.user_id
    JOIN regions rg ON u.region_id = rg.region_id
    JOIN refunds r ON o.order_id = r.order_id AND r.status = '已退款'
    WHERE rg.region_name = '华东'
      AND substr(o.order_time, 1, 10) = '2024-12-31'
      AND o.status IN ('已完成', '已退款')
    GROUP BY o.pay_type
) rf ON d.pay_type = rf.pay_type;

六、结论与局限

  • 瓶颈在语义口径，不在语法。 Valid SQL 在 96%~100%，答案等价 EX 只有 84%~92%，失败集中在缺列、聚合口径、JOIN/过滤条件。
  • 评测口径本身是最大的误差源。 严格 EX 会低估模型 2~28 个百分点（qwen 2 / deepseek 20 / glm 28 pt）；评测集 gold 累计修订 31 条（19 条留档）。做 Text2SQL 评测，先把 gold 和口径打磨干净，比换模型更重要。
  • 提示词收益集中在复杂题。 两模型 × 两档提示的消融显示加强提示总体 +16.0 / +8.3 pt，但 easy 段几乎不动，hard 段达 +20.0 / +22.4 pt——提示词应按难度与题型定向注入，而不是全局堆指令。
  • 局限：hard 仅 15 题，1 题 = 6.7 pt，波动大；消融只覆盖 2 个模型。横向对比三模型均为 50/50 有效题；消融中 deepseek 的 simple 档有 1 题（Q43）接口空输出，按缺失剔除后 n=49，故其 simple→加强的 +8.3 pt 跨了 1 题分母差异，不改变方向。
